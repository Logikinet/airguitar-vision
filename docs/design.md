# 系统设计、模块逻辑与验证

## 课设目标

用户确认了 **方案 A**：左手 6 种简单手势选择 6 个和弦；左手食指也可选择六弦四品的单音；右手上下穿越一个独立的扫弦区域发声。系统使用 Windows + VS Code + 摄像头和扬声器。原始架构保存在 `docs/original_architecture` 以供对照。

## 关键点

MediaPipe 输出两只手的 21 个关键点（0=腕、8=食指尖等）。摄像头画面自拍镜像输入。`HandTracker` 的输出坐标为**像素 x/y**，z 乘以画面宽度；`Fretboard` 的 ROI 用相对比例并每帧换算；`StrumDetector` 的速度单位 **像素/毫秒**；滤波器用离散帧投票。每帧以单调毫秒作为时间基准。

## 模型与手势算法

不使用原方案中对镜头视角要求苛刻的真实四指指型匹配，改为简化手势：先通过关节长度与腕部几何关系估算五个手指是否伸开；0-5 只接受前序连续的食指、中指、无名指、小指结构，带拇指张开形成第五种计数。列表配置于 `src/config.py`。每个新手势必须在一个五帧多数投票窗口中出现至少三次；手部失踪若干帧后失效，从而不会无限播放旧手势。

单音：食指坐标投影到固定矩形 ROI，在 6 条弦×5 个区域中定位 `(s,f)`，其中 `s=0..5`、`f=0..4`。音符 MIDI=对应空弦音符+品位（40,45,50,55,59,64），只播放一个音。

## 扫弦与发声

原设计中参考线的方向与六根弦的方向耦合，实际很难定义。现在右侧独立 `STRUM_ROI` 中间有水平参考线，食指沿竖直法向移动并穿线：`IDLE→APPROACH→TRIGGER→COOLDOWN`；速度阈值（0.22px/ms@540p）、接近距离、轨迹超时以及 180ms 冷却共同抑制误触发。只有右手指尖的投影位于有效线段范围（±10px）内才可触发。前一帧缺失、采样间隔超过 180ms、跳跃超过阈值时不计算速度。

音频采用本仓库 `assets` 中生成的原创合成拨弦 WAV（22050Hz/16bit/mono），pygame 支持并行和弦音轨；和弦分解的相邻音符延迟 12ms，统一队列 `update()` 每帧播放，避免 sleep 卡住摄像头。方向影响音符先后。力度被夹到 0.3..1.0。

## 验证方法

- 不使用 MediaPipe：`python -m pytest -q`，确保几何、手势、滤波、扫弦状态机、资源完整性无回归。
- 完全无 GUI：`python main.py --smoke-test`，生成 `artifacts/smoke_test.png`。
- 有 Windows 图形桌面但无摄像头：`python main.py --demo`，测试 UI、音效、模式切换。
- 有摄像头和网络：`python main.py`，记录真实运行时 FPS（HUD），逐一用手势/单音/扫弦试验；切勿从离线测试推断真实的检测误差或帧率。

## 已知限制

`Hand Landmarker` 模型未打包，首次摄像头模式联网获取；新版本 Mediapipe 不保证带 `solutions.hands`；不同光照和镜头需调整阈值。手势识别由几何规则实现，不做深度重训。调音音色来自合成算法，不是商业吉他采样。按 `1..6` 可强制和弦用于演示音频，而非伪装识别效果。真实摄像头延时、跨机器 FPS 必须用 Windows 实际数据测量。


## 左右手镜像映射修正

实时摄像头默认启用 `DEFAULT_HAND_ROLE_SWAP = True`，用于修正目标设备上观察到的 MediaPipe 左右手标签反转。主程序将归一化后的左手分配给和弦/单音控制，将右手分配给扫弦；HUD 也显示归一化后的手标签。按 `H` 可切换修正状态。合成演示不启用修正；视频文件输入默认不启用修正，因为视频源可能不是自拍镜像画面。
